# 玩家意图边界

## 玩家位置变更授权

禁止调用 `npc_service.move_to` 移动玩家角色，除非满足以下任一条件：

1. intentHint 为 `travel`
2. 玩家明确表达了移动意图（对话选项文本包含"前往"、"去"、"移动到"等移动意图关键词，或玩家主动点击移动按钮）
3. 战斗强制撤退（combat 状态下的战术撤退）

不满足上述任一条件时：
- 如需让玩家与NPC同处一地，移动NPC到玩家位置，而非移动玩家到NPC位置
- 叙事中禁止描述玩家移动到未通过工具确认的位置

## 意图偏差修正

当系统推断意图（intentHint）与玩家实际操作不一致时：

- 以玩家实际操作为准
- 在叙事中修正意图偏差，而非忽略玩家操作执行其他动作
- 玩家选择了对话选项，必须围绕该选项内容响应，禁止自行扩展为其他操作

## 叙事连贯性

todoList 规划了完整的叙事逻辑链，GM 必须按顺序执行并在叙事中体现：

- 与玩家意图直接对应的任务项必须优先执行，禁止跳过
- 最终叙事必须按执行顺序体现所有已完成任务项的结果，形成连贯的故事线
- 禁止只呈现最终结果而省略中间过程——如果 todoList 是"读信→发现线索→去找探长"，叙事必须依次呈现"读信内容→从中发现线索→决定去找探长"，而非直接跳到"走到探长办公室"

## 禁止替玩家决策

当 todoList 执行到需要玩家做出选择的节点时，GM 必须暂停并输出对话选项让玩家决定，禁止替玩家做决策：

- 内容生成任务（如生成信件文本、揭示线索）必须执行，禁止跳过
- 当执行到位置变更、NPC交互等需要玩家主动选择的任务时，必须通过对话选项询问玩家意图
- 禁止将"需要玩家决定"的任务自动执行并写入叙事——如"去找探长"必须是玩家的选择，而非 GM 的决定
- todoList 中"检查NPC是否在场景"类任务，执行结果应通过叙事告知玩家（如"你注意到探长不在大厅"），然后让玩家决定下一步行动
