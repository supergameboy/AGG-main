## 三、根因：架构层"信息传播链"缺失

这不仅是 LLM 幻觉问题，而是 [architecture-standards.md](file:///c:/Users/super/Documents/trae_projects/AGG-main/.trae/rules/architecture-standards.md) 中点到的几个架构缺陷的叠加：

### 缺陷 1：EntityGraph 只能表达 NPC→character 的 awareness，无法表达 NPC→quest/event/info 的 awareness

日志中所有 `set_awareness` 调用的 `targetType` 都是 `character`，**没有任何机制记录"老汤姆知道玩家要调查暗影森林"这个事实**。系统只能表达"老汤姆感知到艾德温这个人"，无法表达"老汤姆知道艾德温的任务"。

### 缺陷 2：没有"NPC 间信息传播"工具

当村长告诉玩家"老汤姆嗤之以鼻"时，这只是村长转述老汤姆的过往观点。**系统没有"村长去通知老汤姆"这个动作的工具**。要让老汤姆合理地"听村长说"，剧情上必须有以下之一：
- 村长对玩家说"我去知会老汤姆一声"→ 然后实际调用一个 `npc_service.notify_npc` 或 `entity_graph_service.propagate_info` 工具
- 或显式建立 NPC→NPC 的 `INFORMED_ABOUT` 关系边

但这些工具和关系类型都不存在。

### 缺陷 3：审核器没覆盖"NPC 说话超出 awareness"的检查

参考 [architecture-standards.md 第十四章 14.5 审核器粗暴检测清单](file:///c:/Users/super/Documents/trae_projects/AGG-main/.trae/rules/architecture-standards.md)，项目有 `EntityGraphAuditor.auditInformationBoundary`，但它检查的是"NPC 是否知道不该知道的事"（防止泄密），**没有反向检查"NPC 说话声称知道某事，但 awareness 数据里没有依据"**。

`audit-agent` 在 [session.log#L3609](file:///c:/Users/super/Documents/trae_projects/AGG-main/dist-release/0.0.7/game_data/logs/session.log#L3609) 显示 `pass: true, failureCount: 0`——审核器通过了，但显然老汤姆的对话内容超出了它的 awareness 数据范围。

## 四、修复方向建议

| 层级 | 修复方案 |
|------|---------|
| **剧情层（最直接）** | Agent 生成老汤姆对话时，应基于 awarenessNote（"亲眼所见，读书人而非战士"）生成，老汤姆只能说"看你这身打扮是个读书人"，不能说"听村长说你要调查暗影森林"。或者让玩家自己透露来意，老汤姆才能知道 |
| **数据层** | EntityGraph 增加 NPC→quest/event 的 awareness 关系类型，让"老汤姆知道调查暗影森林任务"这个事实可以被显式记录或缺失 |
| **工具层** | 增加 `npc_service.propagate_info` 或 `entity_graph_service.inform_npc` 工具，让村长"通知老汤姆"这个动作能被显式调用并留下记录 |
| **审核层** | `EntityGraphAuditor` 增加"对话内容与 awareness 数据一致性检查"——如果 NPC 的话里出现"听 X 说了 Y"，必须能在 EntityGraph 中找到对应的 awareness 依据，否则报 warning |

## 总结

老汤姆那句"我可听村长说了"在剧情上**没有发生**（村长没通知老汤姆），在数据上**没有依据**（awareness 记录的是"亲眼所见"），是 LLM 为了让老汤姆"显得知道玩家来意"而凭空生成的。同一个 Agent 上一轮刚记录"老汤姆第一次见玩家、来源是亲眼所见"，下一轮就生成"听村长说"的对话，是自我矛盾。

根因是架构上"NPC 信息传播链"和"对话-awareness 一致性审核"两个机制缺失，单纯改 prompt 治标不治本。

## 三、Phase 1 核心设计决策

### 决策 1：DialogueConsistencyChecker 实现 LLMChecker 接口（非 ProgramChecker）

**理由**：
- ProgramChecker 是"无 LLM 依赖纯逻辑"，DialogueConsistencyChecker 必须用 LLM 提取语义（"听村长说"→ 信息源=村长）
- LLMChecker 接口 `check(request, ctx, programFailures): AuditFailure[]` 完全匹配
- 内部两步流程是 Checker 实现细节，不破坏接口契约

### 决策 2：AuditAgent 从单 LLMChecker 改为 LLMChecker[] 数组

**理由**：
- 现有 LLMCheckerImpl 处理 `content_quality` 维度（任务契约质量）
- DialogueConsistencyChecker 处理 `dialogue_consistency` 维度（对话-awareness 一致性）
- 两者维度不同、prompt 不同、关注点不同，应该独立
- 改造方式：构造函数 `llmChecker` → `llmCheckers: LLMChecker[]`，audit() 内遍历执行

### 决策 3：DialogueConsistencyChecker 内部两步 LLM 流程

```
Step 1: LLM 提取
  输入：NPC 对话内容 + speaker
  输出：信息源声明数组 [{source: "村长", claim: "矮人要来调查暗影森林", quote: "我可听村长说了..."}]

Step 2: 工具查询（无 LLM）
  对每个声明，查询 EntityGraph:
  - 查 NPC→speaker 的 PERCEIVES 边（如 老汤姆→村长 的 awareness）
  - 查 NPC→claim 相关实体的 PERCEIVES 边（如 老汤姆→quest:暗影森林调查 的 awareness）
  - 输出：每个声明是否有 awareness 依据

Step 3: LLM 综合判断
  输入：对话内容 + awareness 依据（Step 2 结果）
  输出：AuditFailure[]（severity='warning'，含 suggestedFix）
```

### 决策 4：审核器是 warning 不阻断

**理由**：
- 14.1 "审核器辅助 Agent 输出更好质量的数据，不阻塞流程"
- DialogueConsistencyChecker 返回 warning + suggestedFix，Agent 在下一轮 ReAct 可选择修正
- 不强制阻断，避免 LLM 误判合法对话

**接口签名**：
```typescript
// EntityGraphService.informNpc
async informNpc(
  saveId: string,
  informerType: EntityType, informerId: string,    // 信息源（如村长）
  receiverType: EntityType, receiverId: string,    // 接收方（如老汤姆）
  topicType: EntityType, topicId: string,          // 主题（如 quest:调查暗影森林）
  awarenessScore: number,
  awarenessNote: string,                           // "村长告知玩家要来调查暗影森林"
): Promise<{
  topicAwareness: EntityEdge;     // receiver→topic 的 PERCEIVES 边（source="informed_by:村长艾德温"）
  informerAwareness: EntityEdge;  // receiver→informer 的 PERCEIVES 边（记录信息来源关系）
}>;
```

**调用路径**：GM Agent 调用 `entity_graph_service.inform_npc` → 一次调用设置两条 PERCEIVES 边 → 缓存失效 → 返回结果

**改动文件**：
- [audit.ts](file:///c:/Users/super/Documents/trae_projects/AGG-main/packages/shared/src/types/audit.ts) — AuditDimension 新增 `'dialogue_consistency'`

- 新增 `DialogueConsistencyChecker.ts`
- [init.ts](file:///c:/Users/super/Documents/trae_projects/AGG-main/packages/backend/src/agents/init.ts#L799-L806) — 注册 DialogueConsistencyChecker

**两步流程**：
```
Step 1: LLM 提取
  输入：NPC 对话内容（从 dialogue_service.submit_dialogue 的 toolCalls 提取）
  输出：信息源声明数组 [{source: "村长", claim: "矮人要来调查暗影森林", quote: "我可听村长说了..."}]

Step 2: 工具查询（无 LLM）
  对每个声明，查 EntityGraph:
  - 查 NPC→source 的 PERCEIVES 边（如 老汤姆→村长）
  - 查 NPC→claim相关实体的 PERCEIVES 边（如 老汤姆→quest:暗影森林调查）
  - 校验 source 字段是否为 "informed_by:{source}"
  输出：每个声明是否有 awareness 依据

Step 3: LLM 综合判断
  输入：对话内容 + awareness 依据
  输出：AuditFailure[]（severity='warning'，含 suggestedFix）
```
